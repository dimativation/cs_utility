# Гранаты на Cache: от сырых событий к персональному разбору матча

---

## 1. Коротко: идея и результат

**Проблема.** В данных нет итога раунда и матча, поэтому нет и «правильного ответа», по которому можно было бы сказать, хорошая ли граната.

**Решение.** Хорошую гранату определяем через **сравнение с тем, как обычно бывает в такой же ситуации**:

```
10k матчей ──► ЭТАЛОН
                 • каталог раскидок: «откуда → куда», которые повторяют тысячи игроков
                 • нормы каждой раскидки: как часто попадают, с какой техникой, что она даёт
                   (ослепления, урон)

матч игрока ──► каждая граната привязывается к раскидке по намерению (где стоял и куда целился)
            ──► сравнение с нормой: промах? не та техника? слепит своих?
                есть ли с того же места вариант лучше?
            ──► ошибки и подсказки с номером раунда, текстом и картинкой на карте
```

**Что получилось**

| Что | Результат |
|---|---|
| Каталог раскидок | **1 362 раскидки** автоматически (без ручной разметки), покрывают ~51% всех бросков |
| Нормы | у каждой раскидки есть % попаданий, типичная техника и результат (флешки — полезные/вредные, HE и молотовы — урон) |
| Доказательство, что метрики измеряют навык | % попаданий в раскидку растёт с рейтингом (смоки **70% → 83%**); доля вредных флешек падает (**21% → 16–17%**) |
| Объяснение промахов | смок из раскидки «в прыжке», брошенный без прыжка, попадает в **1.7%** случаев против 69% |
| Разбор матча | для каждого из 10 игроков: **ошибки** (подтверждены рейтингом) и **подсказки**, ~0.6 с на матч |
| Дашборд | Streamlit: карта, каталог раскидок, лучшие/худшие флешки, разбор матча |

## 2. Данные: что внутри

Исх

### 2.1. Исходный формат

```
{
  "MatchID": 3831383152580887235,
  "Players": [{"StaticInfo": {"PlayerID": ...}, "PremierRatingNew": 7419}, ...],   # рейтинг есть не у всех
  "Smokes":     [ {GeneralInfo}, ... ],
  "Flashbangs": [ {GeneralInfo, FlashedPlayers: [...]}, ... ],
  "HEs":        [ {GeneralInfo, DamagedPlayers: [...]}, ... ],
  "Fires":      [ {GeneralInfo, DamagedPlayers: [...], FinalInfernoInfo}, ... ],
}
```

Проверка, что `ViewAngle` — это взгляд **жертвы**: чем сильнее игрок отвёрнут от точки взрыва, тем короче ослепление.

| Угол между взглядом и флешкой | Средняя длительность ослепления |
|---|---|
| 0–30° (смотрел прямо) | 2.80 с |
| 60–90° | 1.81 с |
| 90–120° | 1.12 с |
| 150–180° (спиной) | 0.88 с |

**`DamagedPlayers`** (HE, огонь): кому, сколько HP и брони, в каком тике, убит ли.

## 3. Чего в данных нет и как это влияет

| Нет в данных | Что из-за этого нельзя / как обходим |
|---|---|
| Итог раунда и матча | нельзя связать гранату с победой. **Обход:** оцениваем качество исполнения относительно нормы похожих бросков |
| Начало раунда | нет «секунды раунда». **Обход:** `sec_from_first` — секунды от первой гранаты раунда (порядок и интервалы точные, абсолютное время — нет) |
| Позиции игроков во времени, все убийства, экономика, бомба | нельзя понять, перекрыл ли смок обзор или кто был жив. **Обход:** «закуп» оцениваем косвенно по числу гранат команды в раунде |
| **Урон по своим** от HE и огня | метрика «HE/молотов по своим» невозможна; «вред своим» считается только для флешек |
| Результат смока | смок оцениваем только геометрически: встал ли там, где обычно встаёт эта раскидка |
| Рейтинг у ~¾ игроков | сравнение по уровням — только на подвыборке |
| Длинная история игроков | персональная статистика «в среднем ты…» невозможна → **разбор строим по одному матчу**, на событиях |
| Конец раунда | нельзя отсечь гранаты, брошенные после конца раунда («в шутку») |
| Радар и калибровка Cache | **Обход:** карта нарисована из самих данных (`src/mapviz.py`) |

## 5. Каталог раскидок

Логика: `src/lineups.py`; разбор и картинки: `03_lineups.ipynb`.

### Метод

Отдельно для каждой пары **тип гранаты × сторона** (8 групп):
1. **HDBSCAN** на случайной подвыборке 60 000 бросков по 4 признакам: точка броска `(x, y)` + точка падения `(x, y)`.
2. Каждый бросок группы получает раскидку ближайшего кластеризованного броска, если тот ближе **50 ед.** (в 4D); иначе бросок «ситуативный».
3. По каждой раскидке считаем центр броска и падения (медиана), разброс, долю прыжков, приседов и типичный прицел (круговое среднее для поворота).

Прыжок, присед и прицел **не участвуют в кластеризации**: они описывают технику раскидки и потом объясняют промахи.


### Результат

- **1 362 раскидки**, покрывают **51%** бросков (смоки CT — 59%, флешки — 41–44%).
- Медианный разброс падения внутри раскидки **37–55 ед.**, то есть 1–2 ширины игрока.
- `smoke-T-001` — классический смок с T-спавна в прыжке: 100% бросков в прыжке, 16 108 бросков, 5 387 разных игроков.

### Две находки, на которых держится персонализация

1. **Техника однозначна.** Только **3.5%** раскидок имеют смешанную технику (20–80% бросков в прыжке): раскидку либо почти все кидают
   в прыжке, либо почти никто. Значит, «не та техника» — осмысленный сигнал ошибки.
   Раскидки «только в прыжке» — почти все смоки T (54 шт.).
2. **Прицел стабилен.** Медианное отклонение прицела внутри раскидки — **1.5–3°** (у флешек хвост шире: p90 ≈ 12–14°).
   Значит, по позиции и прицелу можно понять, **какую раскидку игрок пытался кинуть**.

## 6. Эталоны (нормы) и привязка по намерению

Логика: `src/norms.py`; доказательства: `04_norms.ipynb`.


### Результат

- По намерению привязано **1 293 622** броска (54%), из них **75% — попадания**.
- Стали видны **324 472 промаха**, которые при привязке по месту падения терялись.
- Там, где есть обе привязки, раскидка совпадает в **81%**.

### Доказательство 1: попадания растут с рейтингом

| Уровень | Смоки | Молотовы | HE | Флешки |
|---|---|---|---|---|
| <5k | 69.9% | 72.3% | 72.0% | 65.2% |
| 10–15k | 75.5% | 77.5% | 75.3% | 69.0% |
| 20–25k | 82.2% | 81.3% | 79.0% | 69.2% |
| 25k+ | **83.3%** | **82.7%** | 78.4% | 67.9% |

У флешек тренда почти нет: геометрическое попадание для них — слабый сигнал (широкий допуск, ситуативные броски).
Поэтому **флешки оцениваем по результату** (полезная / вредная), а не по геометрии.

### Доказательство 2: техника объясняет промахи

| Граната | Раскидка | Бросок без прыжка | Бросок в прыжке |
|---|---|---|---|
| смок | «в прыжке» | **1.7%** попаданий | 69.1% |
| смок | «без прыжка» | 80.7% | **34.8%** |
| HE | «в прыжке» | **0.1%** | 79.8% |
| молотов | «в прыжке» | **0.6%** | 87.8% |

Оговорка: часть эффекта задана самим методом. Если с той же точки есть раскидка без прыжка, бросок привяжется к ней как попадание.
В таблице остаются броски, у которых «правильной» альтернативы нет, то есть реальные промахи.

**Движение — не ошибка.** Молотовы и HE на бегу попадают даже чаще (80–82% против 59–67% стоя): это стандартные run-throw раскидки.

### Цена промаха

| Флешка | Полезных | Вредных | Своих ослеплено |
|---|---|---|---|
| попал в раскидку | 33.5% | 12.4% | 0.23 |
| промах | 28.5% | **17.8%** | **0.33** |

Промах HE обходится дёшево: 8.9 урона против 9.9.

### Раскидки сильно различаются по пользе

- Лучшие флешки: **56–60%** полезных (например, `flash-T-004`: 5 874 попытки, 57% полезных, 6% вредных).
- Худшие: **40–50%** вредных, включая популярные (`flash-CT-001`: ~3 000 попыток, 43% вредных).

Отсюда тип совета «эта раскидка сама по себе плохая, с того же места есть лучше».

## 7. Разбор матча: ошибки и подсказки

Логика: `src/report.py` (`match_report(match_id)`); примеры и проверки: `05_match_report.ipynb`.

### Почему по матчу, а не по истории игрока

92% игроков встречаются в датасете один раз, так что истории нет. И это не нужно: в продукте пользователь загружает матч и получает разбор.
У игрока за матч ~24 гранаты и ~6 флешек, этого мало для долей («40% твоих флешек…»).
Поэтому разбор строится на **конкретных событиях**: «раунд 7: флешка ослепила 3 своих на 3+ с».

### Что ищем

| Проблема | Тип | Как определяем | Вес |
|---|---|---|---|
| **вредная флешка** | ошибка | ослепила своих > 1.5 с, врагов дольше 1.5 с — никого | 1 + 0.3 за каждого ослеплённого своего |
| **промах: техника** | ошибка | промах раскидки, а прыжок не совпадает с нормой (>80% или <20% попавших в прыжке) | 2 |
| **промах раскидки** | ошибка | промах раскидки, которую в норме попадают ≥ 60% (флешки не берём) | 1 |
| **плохая раскидка** | подсказка | с той же позиции (≤ 150 ед.) в ту же область (≤ 400 ед.) есть раскидка лучше: флешки +15 п.п. полезных, HE +5 урона | 1.5 |
| **смерть своего от флешки** | подсказка | тиммейт убит, пока был ослеплён флешкой игрока | 2 |
| **раунды без гранат** | подсказка | команда кинула 6+ гранат (значит, был закуп), игрок — ни одной; одна запись на игрока со списком раундов | 0.5 за раунд |

**Честность сравнения:** нормы раскидок пересчитываются **без анализируемого матча**. Каталог раскидок общий: один матч — 0.01% данных.

**Команды** в данных не указаны. Их восстанавливаем по сторонам в событиях игрока (броски, ослепления, урон) в основное время:
команда A — начала за T, B — за CT.

### Почему одни проблемы «ошибки», а другие «подсказки»

Проверка на 400 матчах с рейтингом, **на гранату** (сильные игроки кидают больше: 1.0 → 1.4 гранаты за раунд, и у них просто больше поводов ошибиться):

| Проблема | <10k | 10–15k | 15–20k | 20k+ | Вывод |
|---|---|---|---|---|---|
| вредных флешек / 10 флешек | 1.92 | 1.70 | 1.70 | **1.48** | ✅ навык → **ошибка** |
| промахов / 10 гранат | 0.60 | 0.56 | 0.52 | **0.52** | ✅ навык → **ошибка** |
| плохих раскидок / 10 гранат | 0.32 | 0.36 | 0.27 | 0.29 | ⚠️ без тренда: выбор раскидки — скорее тактика → **подсказка** |
| смертей своих / 100 флешек | 2.15 | 2.45 | 2.53 | 2.79 | ❌ растёт: сильные агрессивнее флешат под заход → **подсказка** |
| % игроков с раундами без гранат | 67% | 68% | 74% | 73% | ❌ смещение: у сильных команда чаще кидает 6+, проверок больше → **подсказка** |

В «вес ошибок» игрока входят только ошибки.

### Частота (200 случайных матчей)

| Проблема | % игроков, у кого есть | событий на игрока |
|---|---|---|
| раунды без гранат | 70.8% | 0.71 |
| промах раскидки | 61.5% | 1.22 |
| вредная флешка | 55.8% | 1.16 |
| плохая раскидка | 43.8% | 0.73 |
| смерть своего от флешки | 14.0% | 0.16 |
| промах: техника | 1.6% | 0.02 |

### Почему нет оценки «твой уровень ~Xk» по одному матчу

Разброс доли попаданий **между матчами одного уровня** — 13–17 п.п., а разница между крайними уровнями — ~9 п.п.
По одному матчу уровень не определить; это возможно только по истории игрока.

## 9. Ограничения и что можно улучшить

- **Оцениваем исполнение, а не вклад в победу.** Без итога раунда нельзя сказать, что граната «выиграла раунд».
- **Смоки** оцениваются только геометрически (встал ли там, где обычно).
- **Кластеризация** покрывает ~51% бросков. Остальные — ситуативные, для них есть только общие метрики (вредная/пустая флешка, урон).
- **Привязка по намерению** работает в рамках каталога: если игрок кидает «свою» уникальную раскидку, сравнить её не с чем.
- **Эффект техники** частично задан методом привязки (см. раздел 6).
- **Подсказки** («плохая раскидка», «раунды без гранат», «смерть своего от флешки») рейтингом не подтверждены. Это повод посмотреть, а не ошибка.
- **«Раунды без гранат»** не знают, жив ли был игрок, поэтому формулировка содержит «возможно, погиб раньше».
- **Граничные случаи:** флешка, ослепившая всю свою команду на 4+ с, может быть брошена после конца раунда. Времени конца раунда в данных нет.
- **Рейтинг** есть только у ~¼ игроков. Тренды по рейтингу посчитаны на этой подвыборке.
- **Каталог раскидок** при разборе матча не пересчитывается без этого матча (0.01% данных, влияние пренебрежимо).

## 10. Что нужно для продукта и что дальше

**Данные, которые сильнее всего усилили бы разбор**

| Данные | Что дадут |
|---|---|
| итог раунда, время начала и конца раунда | связь гранат с победой; отсечение гранат после раунда; «секунда раунда» |
| позиции игроков во времени, смерти | «перекрыл ли смок обзор», жив ли игрок в «раунде без гранат», откуда добивают ослеплённых |
| инвентарь и экономика | «умер с гранатами», «купил и не использовал» вместо косвенного «раунды без гранат» |
| урон по своим | метрика «HE/молотов по своим» |
| история матчей игрока | уровень «~Xk» по метрикам, устойчивые паттерны, прогресс |
